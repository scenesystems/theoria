Add TeacherTrace as the shared teacher-execution component, with checked signature compatibility, immutable leave-one-out overlays, complete trace evidence, acceptance thresholds, error budgets, execution-time events, and streaming. Signature.digest composes parameter instruction and field overrides and supplies both teacher compatibility and predictor cache identity.

Compile LabeledFewShot, BootstrapFewShot, and BootstrapRS into bound programs with parameter snapshots and concrete reports. LabeledFewShot resets demonstrations and samples independently per trainable predictor. BootstrapFewShot retains cross-example trace duplicates, prewarms uncompiled teachers with labeled examples, and fills only the remaining labeled capacity from unbootstrapped rows. Bound teachers retain their compiled demonstrations.

BootstrapRS evaluates independent zero-shot, labeled, unshuffled bootstrap, and seeded shuffled candidates in order, using full-validation failure-inclusive averages and earliest-winner ties. Its report retains candidate parameters, evaluation reports, and winnerSeed. BootstrapRS ranks and stops on unrounded fractions, whereas DSPy compares `round(100 * ncorrect / ntotal, 2)` percentages. Rounding is monotone, so rankings differ only when unequal fractions round to the same hundredth of a percent (fractions less than about 0.0001 apart): for 0.33331 and 0.33334, DSPy records 33.33 twice and keeps the earlier candidate, while BootstrapRS selects the higher fraction. stopAtScore is an unrounded fraction in [0, 1]: an average of 0.99996 does not stop at stopAtScore 1, where DSPy's rounded 100.0 stops. Exact rounded-percentage ranking and stopping parity is not claimed. Absent or none maxErrors resolves to DSPy's settings default, 10, for every bootstrap compilation and validation pass.

Breaking option and report changes: bootstrap algorithms use metricThreshold, maxErrors, a teacher Module, and teacherSettings routed through ModelBinder. `threshold` is now `metricThreshold`; the `teacher` option is a Module instead of a `LanguageModel` Layer; `fallbackToLabeledFewShot` and `fallbackLabeledDemoCount` are removed. Synthetic teacher instruction changes and labeled-fallback switches and events are removed. BootstrapFewShot defaults to 4 bootstrapped demos, 16 labeled slots, and 1 round. BootstrapRS `numCandidates` is now `numCandidatePrograms` (default 16), explicit `seeds` lists are removed, and label/index-based reports are replaced with seed-based candidate history. These optimizers never install parameters into caller modules; Module.install is the explicit installation operation. No aliases are provided.

Breaking: BootstrapRS no longer runs candidates through effect-search `Optimization.maximize`. It evaluates the seed catalog directly, as DSPy does, so a provided `OptimizationStorage`, `ObjectiveCache` or optimization event stream no longer applies: BootstrapRS candidates are not persisted, cached as objectives, or resumable through effect-search storage. Its report retains every candidate's parameters and evaluation report instead.

Correct Evaluate.maxErrors to abort when the failure count reaches the limit, rather than allowing one extra failure. The generic effect-study maxFailures primitive continues to count allowed failures; one shared internal conversion supplies DSPy-named error budgets.

Use a CPython-compatible integer-seeded MT19937 generator for LabeledFewShot, bootstrap labeled fill, and BootstrapRS. LabeledFewShot now defaults to seed 0. Successive predictor samples share a stream in stable predictor-path order (the fixtures align that order with DSPy's declaration order; differently ordered declarations are not an identity claim); BootstrapRS shuffle and cap draws use separate streams with the same candidate seed, matching DSPy's call order. A pinned CPython fixture asserts bit-exact random, wide getrandbits, rejection sampling, randint, choice, shuffle, and sample outputs.

Parity evidence covers bootstrap-family upstream fixtures, including labeled teacher prewarming, within-trace repeated calls, `teacher_settings` routing with retry rollouts, and the deep-copied teacher's recorded LM calls (the original teacher and student record none), alongside local boundary and immutability tests. Interruption after an accepted trace retains the partial events, emits no completion and leaves the caller's parameters unchanged. LabeledFewShot and BootstrapRS fixtures assert exact demonstration identities and order. Repeated-call evidence verifies exactly one retained demo per predictor per example and full membership in that example's trace demos. Only the particular hash-seeded pick is not reproduced: DSPy seeds it with SHA-256 over Python pickle bytes. TeacherTrace remains lossless; BootstrapFewShot selects the first invocation deterministically. PARITY.md records this limitation and MIPROv2 reuses the generator for demo-set sampling.

Bootstrap retries are example-major, and labeled fill shuffles with a fresh seed-0 stream before sampling with a second fresh stream. BootstrapFewShot resolves absent/none maxErrors to DSPy's default 10, preserves existing default-teacher demos when no prewarm is requested, and treats a zero acceptance threshold as absent. Teacher role, settings and retry rollout are scoped before cache identity is computed. RoundStarted fires when an example first reaches that round; RoundCompleted is emitted after traversal, with cumulative counts through that round. Conditional programs keep the specified every-predictor stop condition, which may collect more examples than DSPy's accepted-example stop.
